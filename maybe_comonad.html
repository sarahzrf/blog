Maybe is a Comonad in OCaml and I Only Partially Understand Why

Some years ago, for the bit, I wrote a scrap of Template Haskell that let you write effectful code using Haskell syntax. You could write, say,

$(effectful [|
  let map' = \f xs ->
        case xs of [] -> []; x:xs' -> f x : map' f xs'
  in map' putStrLn ["hello", "world"]
|])

and this would have type IO [()]. Essentially, I did something like the idiom bracket translation except that I handled more syntactic constructs (with varying success). My translation left free variables alone,1 so as seen above, you could use existing Haskell functions of type A -> M B as though they had type A -> B in your effectful fragments—at a Haskeller’s bullshit level of category-theoretic rigor, “the untranslated snippets are working in the Kleisli category, so Kleisli arrows appear to be ordinary arrows”.

While playing around with this translation, I realized that the existing Haskell id function appears to have the type M a -> a when used inside effectful fragments—the type signature of extract. Continuing to tenuously relate what is going on here to category theory, this corresponds to the fact that “monads become comonads on their Kleisli categories”. In more detail: Suppose \(T\) is a monad on \(\mathsf C\). Then there is an adjunction \(F \dashv U\) with \(F : \mathsf C \to \mathsf C_T\) and \(U : \mathsf C_T \to \mathsf C\) whose monad is \(T\).2 The left adjoint \(F\) is the identity on objects and the right adjoint \(U\) is \(T\) on objects. Hence, the comonad \(F \circ U : \mathsf C_T \to \mathsf C_T\) of the adjunction is just \(T\) on objects (although its behavior on morphisms is a bit different from \(T\)’s)—“\(T\) is a comonad on \(\mathsf C_T\)” (sort of). The \(\varepsilon_A\) of this comonad is given by \(\mathsf{id}_A\) in \(\mathsf C\); this corresponds to the “id becomes some kind of extract” that I saw.

If we keep following this handwavy application of category theory, we arrive at the following: OCaml, say, is a language with exceptions. We can thus (considering only one kind of exception) think of it as “what the Kleisli category of the Maybe monad looks like from the inside”. Therefore Maybe “becomes a comonad on it” (albeit one named option instead), as above, and we can try to derive some OCaml code for comonad operations by following the category-theoretic story.

And I did this, and it worked! It looks like this:

exception Empty

let option_fmap (f : 'a -> 'b) (x : 'a option) : 'b option =
  match x with
  | None -> None
  | Some a -> try Some (f a) with Empty -> None

let option_extract (x : 'a option) : 'a =
  match x with
  | None -> raise Empty
  | Some a -> a

let option_duplicate (x : 'a option) : 'a option option = Some x

Note the nonstandard fmap—the usual one does not give a comonad with this extract and duplicate.

The problem is, I can’t give a principled derivation of this code. To write it, I worked on a basis something like “treat Haskell like it has semantics in some hypothetical Set-like category; then give OCaml semantics in a Kleisli category over that category (ignoring all of the other additional language features besides exceptions) and try to transcribe back into OCaml some functions whose semantics are the data of the previously-discussed comonad on the Kleisli category”.3 But there are a lot of things that are pretty blatantly wrong if you try to make this at all precise, even if we restricted focus to some idealized toy languages instead of Haskell and/or OCaml. Say we had a categorical semantics for such a language with exceptions; then definitions like the ones written above would give rise to constructions inside the category, not ones that operate on it—most notably, the f argument to option_fmap would range in an internal sense over some kind of internal hom, not in an external sense over morphisms of the category (of course these are related, but they are not the same!). And more importantly, in general there is no reason to expect that just because some object exists in the semantics, it should come from a definition in the original language.

Really, I don’t even know how to get as far as having these problems! I’m very unfamiliar with the technical details of connections between effectful languages and category theory, and I don’t know how to actually give a language with try semantics in a Kleisli category like this. I tried going back and checking out Moggi’s original paper about interpreting effectful languages in Kleisli categories, but it doesn’t apply to this case.

I do have a dim sense of how some of this stuff can be resolved. In particular, I think the universality properties of syntactic categories basically resolve some of the issues I complain about above. I just don’t actually know how to actually construct a syntactic category for an effectful language and use such a thing to understand my informal process of deriving the code above.
